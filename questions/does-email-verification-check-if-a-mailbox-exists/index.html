What an email verification API actually checks邮箱验证 API 到底查什么

SHORT ANSWER短答

Six things: address syntax; domain existence and age from registration records; MX routing; disposable, role and free-provider signals; likely typos with a correction; and catch-all risk — combined into a 0–100 score and a valid / risky / invalid verdict.

六样东西：地址格式；域名是否存在、以及来自注册记录的域名年龄；MX 路由；一次性、角色与免费服务商信号；疑似拼写错误及纠正建议；catch-all 风险——合成 0–100 分与 valid / risky / invalid 裁决。

What the checks catch这些检查能抓住什么

Most addresses that hurt you fail these checks long before anything else matters:

  • Typos — gmial.com, hotmial.com: syntactically fine, and the reason confirmation mail vanishes. EmailCheck returns typoLikely plus a suggestion.
  • Dead or parked domains — no MX records, or a domain that no longer routes mail.
  • Disposable domains — throwaway inboxes used to pass a signup gate, flagged per address.
  • Role accounts — postmaster@, admin@ and friends: real, but rarely the audience you meant to mail.
  • Brand-new domains — domainAgeDays from RDAP registration records (null when there is no record — never estimated), a useful fraud and quality signal.

真正会坑到你的地址，绝大多数过不了这几项检查，其他都排在后面：

  • 拼写错误——gmial.com、hotmial.com：格式完全合法，确认邮件却石沉大海。EmailCheck 返回 typoLikely 和 suggestion。
  • 死域名/停放域名——没有 MX 记录，或域名已经不收信。
  • 一次性域名——用来过注册门槛的临时收件箱，逐条标记。
  • 角色账号——postmaster@、admin@ 之类：是真的，但很少是你想发信的对象。
  • 刚注册的域名——domainAgeDays 来自 RDAP 注册记录（无记录返 null，从不估算），是好用的欺诈与质量信号。
