What is the difference between bulk and single email verification?批量邮箱验证和单个邮箱验证有什么区别？

SHORT ANSWER短答

The checks are the same; the moment and the unit differ. Single verification checks one address at the moment it is captured — typed into a signup or checkout form — and shows the full result for that address. Bulk verification checks a list you already hold, usually before a send, and returns per-address verdicts plus summary counts, because the job is segmenting the list, not judging one address. Neither proves a specific mailbox exists: both are domain-level checks of format, MX routing and risk signals. Most teams end up using both, at different points in the address's life.

检查相同，时刻和单位不同。单个验证查的是收集当下的一个地址——刚被输进注册或结账表单的那个——并展示这个地址的完整结果。批量验证查的是你已经持有的一份名单，通常在发送之前，返回逐条裁决加汇总计数，因为要干的活是给名单分段，不是评判某一个地址。两者都不证明某个具体邮箱存在：都是域名级的格式、MX 路由和风险信号检查。大多数团队最后两个都在用，只是用在地址生命周期的不同节点。

Same engine, two moments同一个引擎，两个时刻

A single check happens at capture. Someone types an address into a form, and the check runs before the account exists: it catches the typo (gmial.com instead of gmail.com) while the person is still there to fix it, flags the disposable domain before it becomes an account, and rejects the address whose domain does not exist. A bulk check happens later, to addresses already in a database — collected weeks or years ago, imported from another system, or merged from several sources. The list has decayed since capture, and the question has changed from “is this address well-formed?” to “which of these 5,000 rows should I actually send to?”

单查发生在收集当下。有人往表单里输地址，检查在账号建立之前就跑：它能在人还在场时抓住拼写错误（gmial.com 而不是 gmail.com），能在一次性域名变成账号之前标记它，能拒掉域名不存在的地址。批量查发生在之后，对已经在数据库里的地址——几周或几年前收集的、从别的系统导入的、几个来源合并的。名单从收集那天起就在衰减，问题也从「这个地址格式对不对」变成了「这 5,000 行里我到底该往哪些发」。

What changes in the output输出变了什么

A single result is a full card: verdict, 0–100 score, and every check shown individually — syntax, domain, MX, disposable, role account, free provider, catch-all risk, domain age, and a correction when a typo is likely. A bulk result is that same record repeated per row, plus the part a single check never needs: summary counts and percentages per verdict, disposable and typo totals across the run. The summary is not decoration — it is how you notice that 30% of an imported list is catch-all-risky before you send, rather than after the bounces arrive.

单个结果是一张完整的卡：裁决、0–100 分、逐项检查全展示——格式、域名、MX、一次性、角色账号、免费服务商、catch-all 风险、域名年龄，疑似拼写时还有纠正。批量结果是同样的记录逐行重复，外加单查永远用不到的部分：各裁决的汇总计数与百分比、整轮的一次性域名与疑似拼写总数。汇总不是装饰——它是让你在发送之前、而不是退信回来之后，发现一份导入名单里有 30% 是 catch-all 风险的办法。

Which one you need你需要哪个

If addresses enter through a form, start with single checks at capture — they prevent bad data instead of cleaning it up later, and a typo suggestion at signup is worth more than the same discovery in a pre-send report. If you hold a list — a CRM export, an event list, a legacy database — start with a bulk run. In practice the two compose: single checks keep new data clean, bulk runs re-clean the backlog as it decays. 如果地址是从表单进来的，先上收集当下的单查——它预防坏数据、而不是事后清洗，而且注册当下的拼写建议比发送前报告里发现同一个错误值钱得多。如果你手里是一份名单——CRM 导出、活动名单、老数据库——先跑批量。实际用起来两者是接力：单查保持新数据干净，批量查把存量随衰减反复清洗。单查在验证邮箱地址页试，名单跑在批量检查器试；两者调的是同一个生产 API。
