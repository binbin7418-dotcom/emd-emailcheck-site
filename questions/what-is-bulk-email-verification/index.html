What is bulk email verification?什么是批量邮箱验证？

SHORT ANSWER短答

Bulk email verification is checking a whole list of email addresses in one run — tens, hundreds or thousands at a time — instead of looking them up one by one. Every address gets the same checks a single lookup gets: format, domain and MX health, disposable and role-account signals, likely typos and catch-all risk. What comes back is a scored, segmented list — valid, risky and invalid, with the reason for each row — that you can act on before a send. It is a domain-level check: it establishes that an address is well-formed and its domain is set up to receive mail. It does not prove an individual mailbox exists.

批量邮箱验证，就是把一整份名单一次性跑完——一次几十、几百甚至几千条——而不是逐条去查。每个地址跑的检查和单查完全一样：格式、域名与 MX 健康、一次性与角色账号信号、疑似拼写、catch-all 风险。返回的是一份带分数、分好段的名单——valid、risky、invalid，每行附原因——让你在发送之前就能动手处理。这是域名级检查：它确认的是地址格式正确、域名具备收信条件，不证明某个具体邮箱存在。

How it differs from checking one address它和逐条查的区别在哪

The checks are identical; the unit of work is not. A single check answers one question about one address, at the moment someone types it. Bulk email verification takes a list as its input and a segmented list as its output: every row scored, the risky rows carrying the signal that fired (a disposable domain, a catch-all risk, a likely typo with a correction), and summary counts across the whole run. That shape matters because the decisions are different — you are not asking “is this address OK?”, you are asking “which parts of this list are safe to send to, which need fixing, and which get deleted?”

检查完全相同，工作单位不同。单查回答的是某个人输入某个地址那一刻的一个问题；批量邮箱验证的输入是一份名单、输出是一份分好段的名单：每行带分数，risky 行写明触发的信号（一次性域名、catch-all 风险、疑似拼写及纠正），外加整轮的汇总计数。这个形态重要，因为要做的决策不同——你问的不是「这个地址行不行」，而是「这份名单里哪部分能安全发送、哪部分要修、哪部分该删」。

What a bulk run actually checks一次批量跑到底查什么

Per address: whether the address is well-formed; whether the domain exists and publishes MX records that route mail; whether the domain is a disposable (throwaway) provider; whether the address is a role account such as admin@ or support@; whether the domain looks like a typo of a major provider, with the correction suggested; how old the domain is, from registration records; and a catch-all risk signal for domains that accept mail for every address. The signals combine into a 0–100 score and a valid / risky / invalid verdict. Nothing is sent to the addresses, and no mailbox is probed — the bulk email checker on this site runs exactly this against the production API.

逐条查：地址格式是否合法；域名是否存在、是否发布了能路由邮件的 MX 记录；域名是不是一次性（临时）邮箱服务商；地址是不是 admin@、support@ 这类角色账号；域名像不像主流服务商的拼写错误、并给出纠正建议；域名年龄（来自注册记录）；以及对「所有地址都收」的域名给出 catch-all 风险信号。这些信号合成 0–100 分和 valid / risky / invalid 裁决。不会给这些地址发任何信，也不探测邮箱——本站的批量检查器跑的就是这套、对着生产 API。

When you need it什么时候需要它

Three moments cover most cases: before a significant send to a list you did not just collect (the pre-send hygiene run); when a list changes hands or systems — a CRM import, an acquired list, an export from a form tool — because imports are where typos and dead domains pile up; and when a send bounces more than expected, to find out which segment caused it. If you only ever check one address at a time, you meet the same problems one send too late. How bulk email verification works walks through the run step by step.

三个时刻覆盖大多数场景：给一份不是刚收集的名单做重要发送之前（发送前清洗）；名单换手或换系统时——CRM 导入、买来的名单、从表单工具导出——因为导入环节正是拼写错误和死域名堆积的地方；以及某次发送退信超预期时，用它定位是哪一段出的事。只靠逐条查，你总会晚一次发送才碰到这些问题。批量邮箱验证的运行方式一步步讲了整轮流程。
